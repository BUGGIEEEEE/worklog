## Worklog (기록 형식 worklog/2)
명령: `python3 -B "{WL}" <명령> --tool {TOOL}` — 프로젝트 루트에서 실행한다.
- `| OFF |` 주입이나 .worklog/off가 있으면 작업 지정 질문·save·skip을 하지 않는다. "워크로그 꺼"면 `off --quote "<원문>" [--reason "<이유>"]`, "켜"면 `on` 실행 뒤 skip으로 마친다. 사용자 요청 없이 끄지 않는다.
- 턴 시작: `[Worklog worklog/2 SessionStart` 주입이 보이면 쓰고, 없으면 `show`한다. 대화와 다르면 변경 전에 확인한다. 최초 목표의 값이 바뀌면 유효 결정이 우선한다.
- 현재 작업이 없으면 사용자 지정까지 저장하지 않는다. "<id> 이어서"는 `use <id> --quote "<원문>"`, "새 작업: <제목>"은 `new-work "<제목>" --quote "<원문>"`. 작업이 하나뿐이고 "이어서"면 그 작업을 use한다. 지정이 없으면 "어느 작업으로 진행할까요? [목록] 새 작업이면 제목을 알려 주세요."를 한 번 묻고 `skip "작업 지정 대기"`로 마친다. 임의로 고르거나 만들거나 전환하지 않는다. `use`·`new-work`는 사용자 원문 `--quote`가 없으면 거부된다. 잘못 골랐으면 양쪽 작업에 CORRECTION을 남긴다(사건을 옮기지 않는다). `new-work` 결과에 `notice`(다른 작업의 제약은 적용되지 않음)가 있으면 이어받을 제약을 사용자에게 확인한다.
- `use` 결과가 현재 상태이므로 그 뒤 별도 `show` 없이 바로 저장할 수 있다.
- 턴 끝: `save`를 한 번 실행한다(stdin JSON). 사용자 요청·결정은 원문 일부를 quote에 넣는다. 제약은 사용자가 바꾸기 전까지 유지한다. 읽기 전용 턴(기록할 변화 없음)은 `skip "이유"`로 마친다.
- 무엇으로 기록할지는 세 질문으로 정한다. ① 사용자가 바꾸기 전까지 모든 턴에 적용되는 금지·자료 범위인가 → `constraints`. 이번 턴에만 적용되는 지시(예: "파일은 만들지 마")는 기록하지 않는다. ② 다음 요청이 오면 저절로 끝나는가 → `waiting`. ③ 지금 고른 방법이나 작업량·목표 범위(몇 화까지 등)처럼 바뀔 수 있는 선택인가 → `decisions`(바뀌면 `replaces`). 확인되지 않은 가정은 `waiting`에 `확인 필요: …`로 둔다.
- `status`는 사용자가 작업이 끝났다고 말하기 전까지 COMPLETED로 바꾸지 않는다. 이번 요청이 끝난 것은 `next_action`·`waiting`에 적는다.
- 결정·제약에는 출처가 붙는다. `[사용자]`는 사용자 발언(REQUEST·APPROVAL·D_USER), `[모델]`은 모델 판단(D_AGENT 등). 모델이 스스로 정한 것은 D_AGENT로 남기고 사용자 발언으로 꾸미지 않는다. 사용자 발언과 같은 턴에 모델이 제안한 것(시간 배분 등)은 그 decisions 항목에 `"source": "model"`을 붙인다. `[사용자]` 제약은 사용자 원문 quote가 있어야 해제되고, `[모델]` 제약은 사유만으로 해제한다.
- 산출물 save에는 artifacts와 check를 넣는다. check는 유효 결정·제약마다 **규칙이 지켜졌음을 보여 주는 산출물 본문 구절**을 4자 이상 따옴표로 인용한다. 인용할 구절이 없으면 `미반영: 이유`를 적는다. 작업 방식 제약(스케줄러·알림·전달 방식 등)과 그림·압축 파일처럼 인용할 수 없는 것은 미반영이 정상이다. "행동으로 지켰다"는 본문 반영이 아니다.
- **규칙·제약 문장을 산출물 본문에 써 넣지 않는다(일부만 바꿔 써도 같다).** 그대로 인용하면 결과의 `self_quoted`에 표시되며 반영의 증거가 아니다. "제약을 반영해 달라"는 요청은 본문이 제약을 어기지 않게 쓰라는 뜻이며, 작업 방식 제약은 `미반영: 작업 방식`으로 적는다.
- "기록이 바뀌었습니다" 거부면 `show` 후 재저장한다. "현재 작업이 없습니다" 거부면 사용자에게 작업 지정을 요청한다. Stop 차단이면 save 또는 읽기 전용 skip 후 마친다. 다른 거부도 메시지대로 고친다. save·skip 결과에 `warning`(Hook 미작동 의심)이 있으면 사용자에게 알린다. 코어 소스는 읽지 않는다.
