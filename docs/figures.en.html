README companion · final · measured 2026-10-15
Worklog Keeps Claude Code and Codex from forgetting what was decided, even after the conversation is compacted or a new session starts.
This page goes from install and everyday use to how the record reaches the model.
system · tools instruction files added by Worklog user message tool calls · results model answer

In the real tool, the phrases you type and the text injected for the model are Korean. This page shows English translations, with the Korean original in parentheses where you need to type it.

1. What gets recorded, and where

project folder/
└── .worklog/                 one per project (created at install)
    └── works/                one folder per work
        ├── guide/            work 1  paper-notebook habit plan
        │   ├── events.jsonl    history
        │   └── state.md        current state
        ├── report/           work 2  write the report
        ├── api-docs/         work 3  tidy the API docs
        └── …/                work n
events.jsonl · historyevery decision and result, in order · only ever appended to, never erased
state.md · current statethe goal, decisions, constraints and next step that apply right now · this is what injection ② shows the model (§5)
Works and their records
One work, one foldera "work" is one task with its own record · decisions and constraints of one work never leak into another · a session attaches to exactly one work (§2)
History vs. current
  • every save appends one line to the history
  • the current state is recomputed from the history
  • when a value changes, the old decision stays in the history and only the newest one is in the current state
How to see itask the AI "show the current work state" (현재 작업 상태 보여 줘) · or open state.md · the model gets it automatically at session start (§4–5)

2. How to use it ask the AI to install it; after that you only name the work you want to continue

Install — ask the AI to do it
Say to the AIClone https://github.com/BUGGIEEEEE/worklog and install Worklog in this project (the AI reads AGENT.md and first asks which tools to install for)
The AI runs
git clone https://github.com/BUGGIEEEEE/worklog.git                                   # once
python3 -B worklog/tools/install_project.py --tool claude --root /path/to/project      # once per project
python3 -B worklog/tools/install_project.py --tool codex  --root /path/to/project
clone once · connect each project once · nothing to do after that
Only you can doCodex: in the first session, trust the project, then run /hooks and trust the three hooks it lists · Claude Code: accept the folder-trust dialog if the project is a git repository
Checkask the AI "check the Worklog version" (Worklog 버전 확인해 줘) wl.py version prints it
What you say while working
First session"New work: paper-notebook habit plan guide" (새 작업: 종이 노트 습관 계획 guide) creates the work guide (the id is built from the Latin letters and digits in the title; none → work)
Next session"Continue guide. Write plan.md." (guide 이어서. plan.md 써 줘.) the record is loaded and the work picks up where it left off
Refer to another work"Use the time split decided in guide" (guide에서 정한 시간 배분을 참고해 줘)
the model reads guide's record · only what you asked for is brought over
Delegatingjust tell the AI to delegate · if you open a separate session yourself, start it with "continue guide. subtask: 〈name〉" (guide 이어서. 하위 작업: 〈name〉)
Several worksthe model lists them at session start and asks which one to continue
Savingnothing for you to do · the model saves, or records a skip, at the end of every turn
Now and then
Pause"Worklog off" / "Worklog on" (워크로그 꺼 / 워크로그 켜 · whole project · nothing is recorded while off)
Updatea new version is announced in one line at session start "update Worklog" (Worklog 업데이트해 줘 · runs wl.py update)
Current state"show the current work state" (현재 작업 상태 보여 줘) goal · decisions · constraints · next step

① Rules block — how the model is told to handle the record
Wherethe project's CLAUDE.md (the instruction file Claude Code reads every session) · written once by the installer
Turn startif injection ② is present, treat it as the current state · otherwise read the record with show
Choosing a workonly when the user says "continue 〈id〉" or "new work: 〈title〉" (〈id〉 이어서 · 새 작업: 〈title〉) · never on its own initiative
Savingrun save before the turn ends · for each decision and constraint, quote the line of the artifact that honors it, or state why it does not apply
Changeskept exactly as installed · a new version is applied by reinstalling

7. Good to know

Claude Code and Codex work the same way Pi support planned
  • in both tools the model input gets ① the rules block and ② the injection in the same way
  • both tools read and write the same .worklog/ of a project
  • only the settings file names differ
    file that holds the rules blockhook settings
    Claude CodeCLAUDE.md.claude/settings.local.json
    CodexAGENTS.md.codex/hooks.json
What if another window changed the same work?
  • injection ② is not re-sent on every turn: it arrives at session start (and after compaction) · another session may save the same work in the meantime
  • when this session saves, the tool refuses with "the record has changed"
    the model re-reads the record, merges, and saves again
  • nothing for you to do
Uninstall
  • say to the AI "remove Worklog" (Worklog 제거해 줘) it asks which tool to remove and, only when the last tool goes, whether to keep the records in .worklog/, then runs the uninstaller
  • everything the installer changed is reverted (rules block, hooks, skill files, .gitignore line)
  • --keep-records keeps the records so a later install continues from them · --delete-records removes them
python3 -B worklog/tools/uninstall_project.py --root /path/to/project --tool all --keep-records
one tool only: --tool codex (the records stay while another tool is still installed) · full removal and options: AGENT.md
